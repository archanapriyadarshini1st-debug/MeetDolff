# MeetDolff Companion

A small, self-hosted Next.js + PostgreSQL service that lets **your own AI agents** read your MeetDolff meeting memory over an authenticated, **read-only MCP** endpoint.

A Chrome extension cannot host a public server, so this is the "user-hosted backend" option from `../ARCHITECTURE.md`. The extension remains the source of truth; the companion holds a synced copy that you can delete at any time.

## Status (verified vs. not)

Verified (see `../TESTING.md` for the transcript of the run):
- First-run owner claim, login, sign-out, brute-force lockout (10 failures / 15 min).
- Token creation (hashed at rest, shown once), scopes, rate limit, revocation taking effect on the next request.
- `POST /api/sync` import with strict validation; read-only tokens are refused (403).
- MCP over HTTP JSON-RPC: `initialize`, `ping`, `tools/list`, `tools/call`, notifications (202), batches.
- Tools: `search_meetings` (with timestamps and date range), `get_meeting`, `list_decisions`, `list_action_items`, `generate_report`.
- Owner console driven in real Chromium (login, token creation, import list).

Not built yet:
- The extension does **not** push to the companion automatically. Today you import the extension's exported `meetings/*.json` through the console (or `POST /api/sync` with a `memory:sync` token).
- No write tools (e.g. `create_task`). They need an owner-approval flow first; none are exposed.
- Streamable-HTTP SSE (GET) and MCP OAuth. Auth is bearer tokens only.
- Rate limiting is per token via the audit table (fine for one user, not for a multi-tenant host).

## Run

```bash
cd companion
cp .env.example .env     # set DATABASE_URL
npm install
npm run db:push          # creates the tables
npm run build && npm start
```

Open the page and **claim the companion with a passphrase immediately**. The first claim wins and the owner can't be reset from the UI, so don't expose the deployment before claiming it. Serve it over HTTPS (session cookies are `Secure` in production).

## Connect an agent

Create a token in the console, then:

```bash
curl -s https://YOUR_HOST/api/mcp \
  -H "Authorization: Bearer $MEETDOLFF_TOKEN" -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"search_meetings","arguments":{"query":"database performance"}}}'
```

MCP client config (clients with HTTP-server support):

```json
{ "mcpServers": { "meetdolff": { "type": "http", "url": "https://YOUR_HOST/api/mcp", "headers": { "Authorization": "Bearer <token>" } } } }
```

## Security model

- Tokens: `mdk_…`, 192 random bits, stored as SHA-256 only, revocable, scoped (`memory:read` default, `memory:sync` separate), rate-limited.
- Owner passphrase: scrypt with a per-install salt; sessions are HttpOnly, SameSite=Strict cookies stored hashed.
- Every external call is written to `audit_log`; failures never reveal whether a token existed.
- No CORS headers are set: server-side agents work, arbitrary web pages cannot call it from a browser.
- Tool results come only from synced memory. Reports are deterministic; nothing is generated by a model.
